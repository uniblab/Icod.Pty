# Focused live matching and scripted interaction

**Status:** planning design for the selected continuation of option 8 after merged [PR #7](https://github.com/uniblab/Icod.Pty/pull/7). Implementation and qualification are pending.

## Intent and boundaries

A consumer should be able to exchange a short, deterministic sequence of bytes with a child PTY: wait for a prompt, send bytes, and wait for a response, even when output is split across native reads or arrives between operations. The consumer continues to own its session and output destination. The automation observes bytes only after the existing destination accepts them. It must not turn a match timeout, buffer overrun, or cancelled script into an output-pump failure.

The selected approach is an opt-in, session-owned bounded byte matcher plus a small script runner built on `PtySession.WriteAsync` and `ExpectAsync`. The matcher is installed before the output pump starts, so an early prompt can be retained. One cursor consumes successful matches in order. The existing recording format, optional recorder, `PtyProcess`, stream ownership, and default callers remain unchanged.

Alternative approaches considered: reread the recording stream (requires seekability and cannot reliably match live output), or place an asynchronous unbounded output queue between the pump and script (risks retained payload and shutdown complexity). Neither is selected.

## Proposed public contract

- Add nullable `PtySessionOptions.Automation` of type `PtyAutomationOptions`. A non-null instance enables matching. Its `MaxBufferedOutputBytes` defaults to 64 KiB and must be in the inclusive range 1–1,048,576 bytes. Capture the setting before launch. The opt-in rejects a non-null `PtySessionOptions.Input` to avoid competing scripted and forwarded input. Recording may be enabled independently.
- Add `PtySession.ExpectAsync(ReadOnlyMemory<byte> pattern, TimeSpan timeout, CancellationToken cancellationToken = default)` returning `Task<PtyExpectResult>`. Require a nonempty pattern no larger than the captured buffer cap, a positive timeout no larger than `Int32.MaxValue` milliseconds, and exactly one pending expect. The immutable result reports `Matched`, `TimedOut`, `OutputEnded`, `OutputStopped`, `OutputTimedOut`, `OutputFaulted`, or `BufferLimitExceeded`, together with the number of output bytes consumed through a match when applicable. An unmatched output EOF, stop, drain timeout, or fault completes the waiter promptly; it never waits for its deadline. Method calls without automation fail immediately. Caller cancellation throws `OperationCanceledException` and does not terminate or dispose the session.
- Add immutable `PtyScriptStep.Send(ReadOnlyMemory<byte> bytes)` and `PtyScriptStep.Expect(ReadOnlyMemory<byte> pattern, TimeSpan timeout)` factories. They copy their byte arguments, so later caller mutation cannot change a pending script. Empty sends are allowed; empty expects are rejected. Add `PtyScriptRunner.RunAsync(PtySession session, IReadOnlyList<PtyScriptStep> steps, CancellationToken cancellationToken = default)` returning `Task<PtyScriptResult>`. It executes the steps in order using the session's existing writer and matcher. The result includes completed step count and the failed step index/status, or indicates completion. It does not own/dispose the session, shut down the child, or swallow cancellation and input-write exceptions. The runner rejects a second concurrent run on the same session; direct concurrent input and expect calls are outside its ordering guarantee.
- Freeze names and exact additive signatures in the first implementation tranche against `packaging/PublicApiBaseline.txt`; update the baseline only for intentional additions. No use of callbacks, regex/text decoding, or terminal-control interpretation is implicit in these types.

## Byte and lifecycle semantics

Successful `ExpectAsync` searches forward from the shared automation cursor. The buffer contains output accepted since session startup or the last match, including bytes that arrived before an expect began. A match may span output chunks; on success the cursor advances through the end of the **first** occurrence and any following bytes remain available for the next expect. Output preceding the occurrence is consumed. A timed-out or cancelled expect does not move the cursor; a later expect can still match retained bytes. Search is ordinal over raw bytes, including NUL and invalid UTF-8. A script's send followed by expect therefore cannot lose a fast response between the steps.

After output ends, an expect still searches already accepted buffered bytes first. If no match remains, it reports the output's EOF or fault. Primary-process exit alone does not end matching while output is still draining or held open by a descendant.

Keep only the configured maximum unconsumed bytes. If more output arrives before a match consumes it, latch `BufferLimitExceeded` for the automation path until the session ends; never silently discard prefix bytes and later claim a successful match. The output pump, recorder, and process continue. The error/result exposes counts and status, never captured content. Buffer memory remains bounded regardless of chunk boundaries, repeated mismatches, or a producer that never pauses. Fail fast when a pattern exceeds the cap. Avoid quadratic rescans for long patterns and many small chunks.

Observe each output chunk after `Output.WriteAsync` succeeds and before admitting the next chunk. A destination that partially writes and throws supplies no confirmed chunk to the matcher. Matcher failures never throw from the output pump. Coexistence with recording retains both independent result contracts and preserves accepted output order. `OutputCompletion` and `Completion` remain authoritative for output and process errors. A timed-out script leaves the session alive for the caller to retry or dispose; the sample and package smoke must explicitly dispose their owned sessions on every path. Supplied streams retain their existing ownership settings. Match deadlines use elapsed monotonic time, not a wall-clock timestamp; cancellation must release the pending waiter and all timers. As with existing session I/O, an uncooperative supplied stream or native write may prevent bounded completion despite cancellation.

## Explicit exclusions and acceptance

This increment has no input capture or change to version-1 recording files, timed replay, terminal emulation, screen-aware matching, regex/Unicode matching, branching scripts, secret redaction, generic observer/exporter, or automatic child termination. A script's send bytes may be sensitive; do not log, echo, or record them. Recording remains output/resize only.

Acceptance requires binary and cross-chunk matches, early prompts, fast send/response, consecutive expectations with cursor consumption, EOF/fault/timeout/cancellation/overrun semantics, independent recording, concurrent-call rejection, and no change to disabled sessions. Use controlled streams and a native package-consumer smoke on .NET 8/9/10 across Windows/Linux/macOS x64/ARM64. Keep the documented ConPTY fragmented-query limitation visible; successful matching cannot recover bytes discarded by the native backend. Record Windows laptop checks separately from hosted CI.
